# 安装与维护

## 准备

需要合法安装的 PBZ Steam Windows x64 版本及可用的 Steam。已验证构建和较新版本的自动匹配条件见[兼容说明](COMPATIBILITY.md)。为首次工具、资源下载和转换预留至少 3 GB 空间。

先在游戏中通过原生保存入口保存，再正常退出。安装和备份期间不要运行游戏。关闭任何旧版本加载器或模组管理器的自动部署功能，避免两个工具同时写文件。

## 解压与一键启动

在 Steam 库右键 PBZ → 管理 → 浏览本地文件。把 Release 压缩包中的内容直接解压到该目录：

```text
PBZ/
├─ Launch-PBZMC.cmd
├─ Backup-PBZMC.cmd
├─ Uninstall-PBZMC.cmd
├─ PBZMC/                  # 本模组安装工具、运行文件和许可证
├─ platform/steam/PBZ.exe  # 原游戏文件，压缩包不提供
└─ ProjectPBZ/
```

双击 `Launch-PBZMC.cmd`。首次运行会检查版本及文件冲突，备份存档，在 `PBZMC/cache` 中准备固定版本的资源，再把正式运行文件安装到 `platform/steam`。最后通过 Steam 启动游戏。首次准备比以后启动耗时长，窗口会报告当前转换步骤；不要提前关闭。

从 **0.1.0-alpha.6** 起，**每次模组游玩都从 `Launch-PBZMC.cmd` 启动。直接从 Steam 点“开始游戏”为无模组模式**。两种模式切换前先退出游戏。脚本只为本次启动传入模组参数，不修改 Steam 的持久启动选项，也不在后台等待退出后卸载。即使崩溃，下次正常 Steam 启动仍不加载 UE4SS 或 PBZMC；缓存和模组存档保留。

从旧版升级时，完整解压后必须运行一次新版 CMD，安装新的默认关闭加载器。不要把 `--pbzmc` 手动写入 Steam 的“启动选项”；若曾手动添加，请移除。`--disable-ue4ss` 会优先禁用加载器，使用模组时应移除这项。卸载脚本用于彻底移除安装文件，不是日常模式开关。

原始资源由 Mojang 的官方分发端点、固定提交的 Bedrock samples 及其镜像获取；工具同样固定版本。每个候选来源必须匹配同一个哈希，校验失败的文件不会被安装，会尝试下一来源。无需修改系统 PATH、关闭杀毒软件或以管理员身份运行。若目录不可写，先将 Steam 游戏移到当前账户可写的库目录。

第一次安装后可离线复用资源缓存，但 Steam 和游戏本身的离线要求仍按原游戏执行。不要删除 `PBZMC` 文件夹中的安装记录，否则自动卸载无法区分本模组与其他工具拥有的文件。

## 免下载版与离线迁移

文件名以 `-win64-offline-cache.zip` 结尾的包使用玩家已准备好的同版资源。保留原来的 `PBZMC` 目录，解压新版后双击 `Launch-PBZMC.cmd`。矛、重锤和风弹用到了新版模型、粒子和音效。升级时可先用标准版更新资源，或从已装好同版模组的电脑复制完整缓存。缓存缺失时，安装器也会检查游戏中已安装的资源副本。

在另一台电脑首次离线安装时，先从自己已装好同版模组的电脑完整复制 `PBZMC/cache/runtime-assets` 到目标游戏目录的相同位置，再解压免下载版并启动。安装器按包内清单逐项校验资源。无法找到完整的匹配资源时会停止并提示。没有准备过资源的玩家请选标准包。

## 中国大陆网络与下载失败

双击启动脚本即可使用以下线路，无需另装下载工具或手动替换资源：

| 内容 | 优先来源 | 失败时回退 |
| --- | --- | --- |
| MC 客户端资源、索引、声音、字体 | [BMCLAPI](https://bmclapidoc.bangbang93.com/) | Mojang 原始地址 |
| Bedrock 分类 UI，固定提交 | [jsDelivr Gcore](https://www.jsdelivr.com/network) | jsDelivr 默认线路、Mojang 的 GitHub 原始地址 |
| Python、Pillow、json5 | [华为云镜像](https://mirrors.huaweicloud.com/) | Python／PyPI 原始地址 |
| 固定版本 FFmpeg | [Gyan 原始地址](https://www.gyan.dev/ffmpeg/builds/) | [ghfast](https://ghfast.top/) 转发 Gyan 的公开发行文件 |

镜像是第三方服务，会按地区调度，也可能临时不可用；BMCLAPI 在部分地区会转回 Mojang。下载器连接／读取超时为 20 秒，自动切换来源并重试。支持 Range 的服务器会续传；不支持的服务器会重新下载该文件。损坏的下载会丢弃，完整文件先校验再使用，不关闭 TLS 或哈希校验。

下载中断时**保留 `PBZMC/cache`，重新双击启动脚本**。完整文件不会重复下载，未完成的 `.download` 文件会继续使用。下载记录位于 `PBZMC/cache/downloads.jsonl`；已有安装更新到相同资源配方时无需重新下载或转换。

如需排查镜像问题，可在游戏根目录用 PowerShell 临时切回原站：

```powershell
$env:PBZMC_DOWNLOAD_SOURCE='official'
.\Launch-PBZMC.cmd
```

关闭这个 PowerShell 窗口即可恢复默认镜像策略。若本机代理配置失效，可在同一窗口设置 `$env:PBZMC_DOWNLOAD_PROXY='direct'` 后重试；这仅对本次启动有效，不改变系统代理设置。

GitHub 下载较慢时，可将同一版本 ZIP 的 GitHub 下载链接复制到 [GH Proxy](https://gh-proxy.com/) 或 [GHFast](https://ghfast.top/)，也可从 [Nexus 文件页](https://www.nexusmods.com/phantombladezero/mods/374?tab=files)选择相同版本。下载后运行 `Get-FileHash .\PBZMC-*-win64*.zip -Algorithm SHA256`，按文件名与该版本随附的 `SHA256SUMS.txt` 核对。

alpha.3 已从空缓存完整下载并校验 4 个工具包和 166 个不同的资源输入，生成的 3172 个运行资源逐个匹配固定哈希；该完整下载在关闭进程代理的日本出口完成。另通过 Globalping 的中国大陆电信、联通、移动节点进行 HTTPS Range 下载抽查，确认各类资源至少有一条可用线路，并据此将 Bedrock 切到 Gcore、FFmpeg 原站优先。节点抽查不等于每个地区的完整安装测试，第三方线路也不能保证永久可用。

## 备份与恢复

需要一起备份：

- `ProjectPBZ/Saved/SaveGames/`：PBZ 原生存档。
- `ProjectPBZ/Saved/*.sav`：原生设置／关联数据。
- `platform/steam/ue4ss/Mods/PBZMCProbe/Scripts/pbzmc-data/`：MC 背包、建筑及原生存档检查点关联数据。

`Backup-PBZMC.cmd` 会在游戏关闭时逐文件复制并校验，保存到 `PBZMC/backups/日期-编号/`。首次安装也会做一次备份。建议另留一份在游戏目录以外，避免卸载整个游戏时一并丢失。Steam 云存档通常不会替你备份模组数据。

恢复时先关闭游戏和自动同步，保留当前文件的另一份备份，再将**同一次备份**中的原生存档和模组数据按原路径一起恢复。不要混合不同时间点的两套数据。确认恢复正确后再决定 Steam 云冲突采用哪一份；本脚本不替你选择或覆盖云存档。

建筑和物品变化只在原生保存入口保存时写入检查点。文件备份无法取代尚未发生的游戏内保存。

### 大存档与读档失败

“只有史蒂夫、没有 MC 界面”需要按日志区分文件读写失败和 JSON 大小限制，不能只根据磁盘存档大小判断。

### 长路径导致首次初始化或备份失败

旧版在 Windows 未启用长路径支持时，可能首次进档只有史蒂夫，没有快捷栏、B 背包或 H 提示；重装／卸载又在 `PBZMC/backups/.../player-store/` 下报告“未能找到路径的一部分”。原因是带双哈希的检查点临时文件、以及加上备份目录后的文件路径超过了传统的 260 字符限制，并非 MC 资源必然缺失。

修复版的存档读写、校验和备份使用 Windows 扩展路径，不需要管理员权限或修改系统注册表，原有文件名、哈希和存档关联保持兼容。**先退出游戏，将修复版解压覆盖到同一游戏根目录，运行新版 `Backup-PBZMC.cmd`，再运行 `Launch-PBZMC.cmd`。** 不要先卸载旧版或删除 `pbzmc-data`；如果旧备份脚本本身报错，应先更新安装工具再备份。

若目录权限、磁盘空间等问题仍导致读写失败，游戏会提示 MC 读档失败，`UE4SS.log` 中的 `PBZMC-IO` 会记录失败操作、路径长度、错误码和完整路径。该次初始化会停止，避免逐帧重试产生无用检查点。修复原因后重新载入存档或重启游戏。

### MC 旧档失败时自动重建

确认 PBZ 已成功加载且存档身份有效后，如果配套的 MC 检查点、物品或建筑数据缺失／损坏／不兼容，会自动创建独立的 MC 数据，恢复初始装备和空建筑，并显示 20 秒提示。**不重置 PBZ 的角色、剧情或关卡，不覆盖失败的 MC 文件，也不主动调用原版保存。** 新 MC 进度仍在下一次原版存档点保存。

旧文件原位保留作为恢复依据，不再复制整个存档目录；每个失败检查点只有一套替代数据和一条小型关联记录，再次读同一档会复用。之后的每个原版存档点关联其自己的 MC 快照，不串用最新背包。请连同 `pbzmc-data/player-store` 中的 `.recovery.json` 文件一起备份。不要只删除关联记录，否则下次读旧档可能再次初始化。手工恢复完整、有效的原 MC 检查点后，会优先使用原数据。

PBZ 自身读取失败、原生接口版本不匹配、存档超出原生桥安全上限或磁盘不可写时，不能安全建立关联，会明确报错并停止该次尝试，不改 PBZ 存档。

### 存档 JSON 大小限制

alpha.4 及以前的存档桥最多读取 262,144 个 UTF-16 代码单元，写入前的 JSON 又限于 252 KiB。限制作用于游戏在内存中展开的文本：不能用磁盘上 `.sav` 的大小判断，也没有固定的出错章节。典型表现是史蒂夫外观仍在，但读档后背包、快捷栏和建筑无法加载。旧日志往往先出现 `native FString length exceeds the probe bound`，随后只剩 `formal-inventory-load-unresolved`。

修复后的存档桥最多接受 **8 MiB（8,388,608 字节）的 UTF-8 JSON、400,000 个 JSON 值**；转换前也检查 UTF-16 长度。写入身份、检查点或快捷栏标记时，写入前的文本最多 **8,384,512 字节**，另为新增字段预留少量节点。超过限制时不会截断数据或另建空背包；在 `platform/steam/ue4ss/UE4SS.log` 搜索 `MC 读档失败`、`MC 存档点未能确认保存` 或 `save-limit:`，可看到触发的指标、实测值和上限。存档点写入失败时，请勿假定本次背包或建筑改动已保存。

出现上述旧版报错时，先退出游戏，用 `Backup-PBZMC.cmd` 将**当前原生存档和模组数据一起备份**，安装含此修复的版本并完全重启，再读取同一个存档。仅触发旧上限并不需要回退进度或删除 `pbzmc-data`。升级前留一份配套备份，确认新版可用后可手动清理多余的历史备份；无需每次启动或每次换章都复制一份完整目录。

## 更新与卸载

更新前保存、退出、备份，查看新版本说明后再解压覆盖安装工具并运行启动脚本。脚本仅更新它能确认归属的文件；手动改过的文件或其他模组的冲突文件会阻止覆盖。

双击 `Uninstall-PBZMC.cmd`，脚本再次备份并只移除记录内、哈希匹配的运行文件。不删除存档、模组数据或缓存。被修改的文件会保留并显示其路径，需自行检查。回退版本时，程序文件与存档数据格式需要同时兼容，不能只把旧 DLL 覆盖回来。

已有其他 UE4SS 模组的安装不能直接视作兼容。特别是同名 `dwmapi.dll`、UE4SS 版本或全局配置不同，脚本会拒绝覆盖。请使用干净的游戏安装，或由熟悉 UE4SS 的使用者手动合并；不要把本包中的配置当作其他模组的通用配置。

## 常见问题

- **提示 `PBZMC-HOST`：** 较新游戏版本会自动尝试匹配。如果报告引擎不兼容、缺少入口、多个匹配或调用目标改变，请保留完整提示，连同游戏版本发到 GitHub Issues。
- **资源准备失败：** 检查网络和磁盘空间，保留 `PBZMC/cache` 后重试。转换日志位于 `PBZMC/cache/asset-work/`。哈希错误应重新下载该缓存文件，勿关闭校验。
- **仍是原版人物／没有 MC UI：** 确认使用启动脚本完成首次准备；检查 `platform/steam/ue4ss/UE4SS.log`。不能在游戏运行时替换 DLL。
- **缺少 VC 运行库 DLL：** 安装微软官方 [Visual C++ 2015–2022 x64 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。不要从不明网站下载单个 DLL。
- **检查安装文件：** 在 PowerShell 中执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\PBZMC\Manage-PBZMC.ps1 -Action Verify`。
- **卡顿：** 首次游戏着色器编译和资源转换分别属于游戏／安装阶段。大量实体、透明方块与复杂红石仍有开销，早期版本建议逐步增加建筑规模。
